# Architectural Decisions

This document records the key decisions made during Octarine's development, so that future contributors (human or AI) understand *why* things are the way they are.

---

## License: GPL v3.0

**Decision**: Use GPL v3.0 instead of MIT or Apache 2.0.

**Rationale**: The author wants to prevent the application from being forked into a proprietary/closed-source product. GPL v3 ensures that all derivative works remain open-source. Patent protection (present in Apache 2.0) was not considered necessary.

---

## Android Minimum SDK: API 26 (Android 8.0)

**Decision**: Set `minSdkVersion = 26` in `android/variables.gradle`.

**Rationale**:
- The author's explicit requirement: the app must work starting from Android 8.
- Capacitor's `ServiceWorkerController` requires API 24+, so API 26 comfortably covers this.
- Android 8.0 (Oreo) was released in 2017 and still covers the vast majority of active devices.

---

## JDK 17 (not 21)

**Decision**: Use JDK 17 (JetBrains Runtime) instead of JDK 21.

**Rationale**: JDK 21's new `posix_spawn` process mechanism causes `posix_spawn failed, error: 0` errors on macOS 11 (Big Sur). JDK 17 is the current LTS standard for Android development and works reliably across all supported platforms.

---

## Kotlin Version Pinning: 1.8.22

**Decision**: Force all Kotlin dependencies to version 1.8.22 via `resolutionStrategy.eachDependency` in the root `android/build.gradle`.

**Rationale**: Capacitor plugins pull in conflicting versions of `kotlin-stdlib-jdk7` and `kotlin-stdlib-jdk8` (e.g., 1.6.21), causing `Duplicate class` errors during `checkDebugDuplicateClasses`. The `eachDependency` rule uniformly overrides any Kotlin dependency to 1.8.22 across all subprojects.

---

## Adaptive Layout: `useOrientation` Hook

**Decision**: Use a custom React hook `useOrientation` that compares `window.innerWidth > window.innerHeight` to switch between `HorizonColumns` and `HorizonRows` components.

**Rationale**:
- Pure CSS media queries don't give us explicit state control needed for conditional rendering of completely different component trees.
- The logic "width > height = columns, otherwise rows" works universally: phone portrait → rows, phone landscape → columns, tablet portrait → rows, tablet landscape → columns, desktop → columns.
- Breakpoints were considered redundant — orientation alone is sufficient for this use case.

---

## Project Name: Octarine

**Decision**: Rename from `Tempo` to `Octarine`.

**Rationale**: "Octarine" is the eighth color of the Discworld (Terry Pratchett), "the color of magic," visible only to wizards and cats. It reflects the app's philosophy of revealing the "invisible" structure of time and horizons. The name is short (3 syllables), unique, and has literary depth for those who recognize the reference.

---

## Local Storage Key: `octarine-tasks`

**Decision**: Use `octarine-tasks` as the localStorage key (was `tempo-tasks`).

**Rationale**: Changed during the rename refactor to avoid data collision with any previous test installations. Note: this intentionally clears existing tasks in the browser — acceptable for a pre-release development phase.

---

## Build Automation: `build.sh`

**Decision**: Create a single bash script `build.sh` that builds both Android APK and macOS DMG.

**Rationale**: The build process involves multiple steps (npm install → vite build → cap sync → gradle assembleDebug → electron-builder). A single script reduces cognitive load and ensures consistent builds. The script is resilient to Electron build warnings (which don't prevent DMG creation).

---

## Capacitor File Ownership

**Decision**: Never manually edit `android/app/capacitor.build.gradle`.

**Rationale**: This file is auto-generated by `npx cap sync android`. Any manual changes will be overwritten on the next sync. All customizations should go in `android/app/build.gradle` or `android/build.gradle` (root).

---

## macOS 11 (Big Sur) Compatibility

**Decision**: Target macOS 11 as the primary development platform.

**Rationale**: The author uses a MacBook Pro Mid 2014, which officially supports up to macOS 11. All tooling choices (Node 20, JDK 17, Android Studio) are verified to work on this OS version. The `ssh-add -K` flag (not `--apple-use-keychain`) is used for SSH key management on this OS.
